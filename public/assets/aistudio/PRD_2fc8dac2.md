# Leaf. — Product Requirements Document (PRD)

- **문서 버전:** v1.1 — 공식 로고 자산 적용
- **기준일:** 2026-11-14
- **개발 환경:** Claude Code
- **제품 유형:** 반응형 브랜드 웹사이트 + 에디토리얼 콘텐츠 + 커뮤니티 + 외부 커머스/예약 연결
- **상태:** 개발 착수용 초안 (사업자/외부 플랫폼 연동 및 법무 정책은 출시 전 확인 필요)

> Leaf.는 옷을 판매하는 것으로 끝나지 않는다. 충분히 알고 선택한 옷을 오래 입고, 돌보고, 때로는 다시 순환시키며, 그 사이에 자신의 취향과 삶을 돌아보고 서로의 이야기를 나누는 브랜드 플랫폼이다.

---

## 1. 제품 비전과 의사결정 원칙

### 1.1 브랜드 정의

- 핵심 고객: 자신의 취향을 이미 알고, 바쁜 일상에서도 그 취향을 지키고 싶은 30–40대 여성을 중심으로 하되 연령으로 접근을 제한하지 않는다.
- 브랜드 제안: **“오래도록 나다운 선택.”**
- 브랜드 성격: **Clothing & Life**, 쇼핑과 라이프스타일이 공존하는 매거진형 브랜드 공간.
- 가치: **CHOOSE** 충분히 알고 선택하기 / **CARE** 오래 돌보고 사용하기 / **REFLECT** 스스로를 알아가기 / **CONNECT** 경험과 관계 나누기.
- 소비를 무조건 억제하거나 구매 고객만을 우대하지 않는다. 제품 품질과 정보 투명성, 사용·수선·순환 경험으로 가치를 보여준다.

### 1.2 제품 설계 원칙

1. **모바일 우선:** 상품 구매 경로와 참여 동선은 짧고 분명해야 한다.
2. **둘러보기는 공개:** SHOP, ARCHIVE, JOURNAL, MINDSET, CIRCLE 게시글, EXPERIENCE는 로그인 없이 열람할 수 있다.
3. **참여할 때만 로그인:** CIRCLE 글·댓글 및 재주문 희망 표시에는 Leaf. 간편 로그인 필요.
4. **브랜드는 하나, 거래의 출처는 분명하게:** 초기 의류 주문은 네이버 스마트스토어, 프로그램 예약·결제는 네이버 예약을 우선 검토한다. Leaf. 사이트는 결제 성공이나 주문 확정을 추정하지 않는다.
5. **이야기는 남는다:** 상품 판매 종료 후에도 제품 설명·제작 기록·관리 정보는 지속 공개한다.
6. **운영자가 감당할 수 있는 MVP:** 필수 기능과 이후 확장 기능을 엄격히 분리한다.
7. **개인적 성찰을 데이터화하지 않는다:** 초기 MINDSET에서는 고객의 개인 답변을 입력받거나 서버에 저장하지 않는다.
8. **접근성·보안·속도:** 디자인보다 핵심 행동의 가독성, 안전성, 일관성을 우선한다.

### 1.3 성공 가설 (검증 필요, 사실로 간주하지 않음)

- 제작 과정과 소재 설명이 선주문 신뢰와 구매 의향에 도움이 된다.
- 옷 관리 팁과 고객 이야기가 판매가 없는 기간에도 재방문 동기를 만든다.
- 재주문 희망은 생산 계획의 참고 지표가 될 수 있으나 실제 구매량을 대변하지 않는다.
- 무료 콘텐츠/모임 경험이 브랜드 관계의 출발점이 될 수 있다.

## 2. 범위, 우선순위, 출시 단계

### P0 — 최초 공개 필수(MVP)

- 반응형 디자인 시스템, 공통 헤더·푸터·모바일 내비게이션, 브랜드 소개.
- SHOP: 분류(ROBE / TEE / KNIT / BOTTOMS), 상품 목록·상세, 상품별 주문 회차와 판매 상태, 외부 스마트스토어 구매 링크.
- 제품별 `Making Updates`: 확인된 제작 진행 공지와 업데이트 날짜. 일반 주문 배송 상태와 구별.
- ARCHIVE: 기획 제품에 한해 `Piece.###` 표시. 미부여 상품도 일반 제품 페이지 유지.
- JOURNAL: 리프의 메시지·제작·사람 이야기, 게시 및 연결 관리.
- MINDSET: 공개 질문·짧은 에세이·작은 실천, 질문 복사 기능. **개인 기록 없음.**
- CIRCLE: 공개 열람, 간편 로그인, 독립 게시글(제목/본문/선택 사진 최대 3장), 댓글/질문, 관리자 승인, 게시글·댓글 신고, 본인 수정·삭제.
- 재주문 희망: 로그인 회원의 상품/옵션별 관심 표시·취소, 중복 제한, 관리자 집계.
- EXPERIENCE: 온·오프라인 프로그램 공개 목록·상세, 네이버 예약 링크, 모집 상태 수동 관리.
- MY LEAF.: 닉네임/계정 관리, 재주문 희망 목록, 내 글·댓글 및 승인 상태 확인.
- 관리자: 콘텐츠·상품·회차·제작 공지·프로그램 링크·게시글 승인·신고·회원 관리.
- 필수 정책 페이지와 시스템 상태(로딩/오류/빈 목록/링크 없음), 기본 검색엔진 설정.

### P1 — 출시 후 관찰·개선

- 재오픈 알림 신청(선택 동의), 콘텐츠 북마크, 프로그램 관심 목록.
- CIRCLE 키워드 검색·고급 필터, 게시글 알림, 관리자 운영 통계 및 제한적 자동화.
- 실제 사용 데이터에 따른 메인 콘텐츠 구성 실험.

### P2 — 장기 확장

- 자체 쇼핑몰 주문·결제·취소/환불/배송 시스템 및 결제 제공자 연동.
- 외부 주문/예약 데이터의 **정식 API 및 명시적 동의에 따른** 연계.
- SECOND LIFE: 중고·나눔·리폼 프로젝트 (거래 정책·신고·분쟁·운영 역량 검증 후).
- 고객 간 모임 생성, 오프라인 커뮤니티, 사용자별 개인 아카이브.
- MINDSET 비공개 디지털 기록은 별도의 개인정보·보안 설계 및 수요 검증 후 재결정.

**MVP 제외:** 자체 결제, 자체 예약 확정·정원 동기화, 별도 주문 DB, 개인 심리 데이터 보관, AI 상담, 고객 간 DM, 모든 브랜드 중고거래, 자동 생산 상태 추정.

### 3.1 상단 내비게이션(데스크톱)

`Leaf. 로고` | `SHOP` | `ARCHIVE` | `JOURNAL` | `CIRCLE` | `EXPERIENCE` | `MY LEAF.(프로필)`

- **MINDSET은 JOURNAL의 탭/하위 영역**, 독립 URL을 갖는다. 메뉴 과밀을 방지하되 직접 링크 가능하게 한다.
- PRE-ORDER는 상품 카테고리가 아닌 **판매 상태와 홈 주요 섹션**.

## 4. 비주얼 방향과 디자인 시스템

### 4.1 Creative Direction

- **Warm Human Journal**: 일상과 옷이 공존하는 사진, 자연광·생활감·실제 사람·소재의 질감.
- 시각 질서: 충분한 여백, 에디토리얼 레이아웃, 절제된 서체. 과한 베이지 감성/상투적인 힐링 이미지는 지양.
- 실제 Leaf. 제품·제작 현장·고객 사용 허락 사진을 우선. 외부 스톡/AI 이미지를 최종 상품 및 실제 고객 사용 증거로 오인시키지 않는다.
- **공식 브랜드 자산은 사용자 제공 워드마크와 심볼을 확정본으로 사용한다.** 텍스트로 Leaf.를 새로 그리거나 유사 서체·AI 생성 로고·임의의 잎 아이콘으로 대체하지 않는다.
- 브랜드 에셋은 프로젝트의 `public/brand/` 경로에서 직접 참조한다. 구체적 경로 및 사용 규칙은 4.2.1절을 따른다.

### 4.2 디자인 토큰 초안

| 토큰 | 값 | 용도 |
|---|---|---|
| `color.bg` | `#F5F1E9` | Warm Ivory 기본 바탕 |
| `color.surface` | `#FFFFFF` | 카드/입력 |
| `color.linen` | `#E4DACB` | 구획/배경 |
| `color.navy` | `#26364C` | 브랜드 포인트/중요 액션 |
| `color.olive` | `#777A66` | 부차적 강조 |
| `color.text` | `#353832` | 본문 |
| `color.muted` | `#656860` | 보조 텍스트 (대비 검사 필수) |
| `radius` | 4–12px 범위 | 단정한 카드/버튼 |

- UI/한글: 접근 가능한 현대적 산세리프. 영문 헤드라인은 편집형 서체를 테스트하되 웹 폰트 로딩 최적화.
- 지정 로고의 원본 폰트가 없어도 **로고 이미지 에셋**으로 처리.
- 텍스트/버튼 배색은 WCAG AA 수준 대비를 목표로 측정. 포인트 올리브를 작은 텍스트에 무조건 사용하지 않는다.
- 최소 터치 영역 ~44×44 CSS px, 키보드 조작, 명확한 포커스 스타일, `prefers-reduced-motion` 대응.

### 4.2.1 공식 Leaf. 로고·심볼 적용 규칙 (P0 · 필수)

**소스:** 2026-11-14 사용자 제공 이미지 2종. 이 PRD와 함께 전달된 `public/brand/` 디렉터리가 필수 개발 자산이다. PRD 파일만 복사하고 에셋을 누락하면 요구사항을 충족하지 못한다.

| 자산 | 파일 경로 | 역할 |
|---|---|---|
| 워드마크 적용본 | `/brand/leaf-wordmark.png` | 헤더, 푸터, 로그인, 브랜드 소개의 기본 로고 |
| 심볼 적용본 | `/brand/leaf-symbol.png` | 작은 공간의 브랜드 표시, 계정/로딩 화면의 보조 표시(로딩 애니메이션 필수 아님) |
| 브라우저 아이콘 | `/brand/favicon-32.png` | 탭 파비콘 |
| Apple 홈 화면 아이콘 | `/brand/apple-touch-icon.png` | 모바일 아이콘 후보(흰 배경/투명 배경 표시 정책은 기기에서 검증) |
| 고해상도 아이콘 | `/brand/icon-512.png` | 메타데이터 및 향후 PWA 준비용, PWA 구현은 P0 범위 아님 |
| 원본 보존 | `/brand/leaf-wordmark-original.png`, `/brand/leaf-symbol-original.jpeg` | 사용자 업로드 원본. 변경·덮어쓰기 금지 |

**원본 처리 근거:** 업로드된 워드마크 PNG는 1638×2048 투명 캔버스에서 실제 글자 영역이 작아 여백만 제외한 적용본 PNG를 별도로 만들었다. 심볼 JPEG는 흰 배경이므로 웹 레이아웃을 위해 흰 배경을 투명 처리한 적용본 PNG를 만들었다. 원본을 반드시 함께 보존하고, 적용본이 원본과 시각적으로 일치하는지 개발 화면에서 검증한다. JPG 압축 노이즈로 일부 가장자리가 거칠 수 있으며, 벡터 로고(SVG)는 **제공되지 않았다**. 기존 로고를 자동 벡터화하거나 재디자인한 결과물을 공식 로고로 간주하지 않는다.

**컴포넌트:** `BrandLogo`(wordmark/symbol variant, 크기·장소를 props로 제어)를 만들어 전 페이지에서 재사용한다. Wordmark는 `img`/`next/image`처럼 원본 비율을 유지하는 이미지로 표현하고 `object-fit: contain`, `width: auto`, `height: auto` 또는 컨테이너 높이 제한을 사용한다. **늘리기·찌그러뜨리기·획 수정·자간 변경·임의 회전·필터를 통한 무단 재색상화 금지.** 시각적 최소 여백을 두고 이미지가 실제보다 작아 보이지 않는지 확인한다.

**권장 배치:** 데스크톱 헤더는 워드마크를 홈페이지 링크로 사용하고 높이 약 32–42 CSS px 범위에서 조정한다. 모바일 헤더는 약 28–36 CSS px 범위에서 확인한다. 푸터는 동일 워드마크를 축소해 사용한다. 심볼은 정사각형 파비콘·브랜드 보조 장식에 사용하되 텍스트 `Leaf.`를 심볼 대신 기본 로고로 사용하지 않는다. 제목 등 일반 텍스트는 별도 웹 폰트로 조판할 수 있지만 워드마크 자체는 이미지 자산이다.

**대비/배경:** 현재 파일은 검정색 로고이므로 밝은 Warm Ivory/White/Linen 배경을 기본으로 사용한다. 딥네이비 등 어두운 배경에 로고를 올릴 때는 명도 대비를 실제로 검증하고, 승인된 반전 로고 파일이 없으면 **밝은 로고용 영역을 마련**한다. CSS `invert()`로 임의 변형하여 공식 로고를 만든 것으로 처리하지 않는다.

**접근성:** 로고가 홈으로 이동하는 링크라면 접근 가능한 이름은 `Leaf. 홈으로 이동`; 중복 이미지 대체 텍스트는 문맥에 맞게 처리. 비장식 심볼은 `Leaf. 심볼`, 장식용 심볼은 빈 alt로 지정한다. 파비콘/메타데이터는 생성한 실파일만 가리키고 깨진 경로를 허용하지 않는다.

**로고 QA:** ① 데스크톱·모바일 헤더에서 실제 `Leaf.` 워드마크가 선명하고 잘리지 않음 ② 푸터·로그인 화면에서 동일 자산 사용 ③ 심볼이 파비콘에 정상 출력 ④ 모든 이미지의 원본 종횡비 유지 ⑤ 라이트 배경에서 대비 확보 ⑥ 어두운 배경에서 로고가 사라지지 않음 ⑦ 개발/배포 환경에서 `/brand/...` URL이 실제 응답 ⑧ 원본을 변경하지 않았음을 확인.

### 4.3 히어로: 확정 기본안

- **이미지:** 일상 공간 속 Leaf. 니트 착용자 + 자연광 + 물성 + 좌측 문구가 놓일 여백. 진실한 라이프스타일 장면.
- **카피 오버라인:** `A LIFE IN YOUR OWN RHYTHM`
- **헤드라인:** `오래도록 나다운 선택.`
- **서브 카피:** `옷을 고르는 마음에서 시작해 삶의 이야기로 이어지는 브랜드, Leaf.`
- **CTA 1:** 판매 상태에 따라 `현재 선주문 보기` / `다음 선주문 미리 보기` / `지금 소개하는 옷 보기`.
- **CTA 2:** `브랜드 이야기 읽기` (ABOUT으로 이동).
- 데스크톱: 가로 이미지, 왼쪽 중앙~하단 텍스트, 이미지 대비 가독성 확보. 풀뷰포트 높이를 강제하지 않고 콘텐츠 접근 유지.
- 모바일: 별도 세로 크롭 또는 모바일 이미지, 짧은 텍스트·명확한 CTA, 첫 스크롤 근처에 Current Piece.
- 히어로 텍스트는 가능한 한 HTML 텍스트로 구현해 읽기·접근성·반응형을 보장.

## 5. 핵심 사용자 시나리오 및 요구사항

### 5.1 방문자 — 상품 선주문

**사용자 목표:** 충분한 정보를 본 뒤 안전하게 외부에서 구매한다.

1. 홈 Current Piece 또는 SHOP 진입.
2. 제품 상세에서 이미지, 가격, 사이즈, 혼용률, 관리법, 판매 기간, 예상 출고일 및 취소·교환 안내를 확인.
3. `PRE-ORDER OPEN` 회차에서 `스마트스토어에서 주문하기` 클릭.
4. **검증된 해당 상품의 외부 URL**로 이동, 네이버에서 주문·결제.
5. Leaf.로 돌아와 제품별 Making Updates/CIRCLE 탐색 가능. Leaf.는 주문 여부를 자동 판단하지 않는다.

**필수 상품 상세 표시:**

- 공식 상품명/슬러그/카테고리/컬러/사이즈/혼용률/착용 정보/원산지 등 해당 판매에서 요구되는 상품 정보.
- 기본 상품 사진과 디테일 사진, 접근 가능한 대체 텍스트.
- 실판매 가격 및 할인 안내(해당 회차 기준), 배송비, 선주문 시작·종료(KST), 예상 출고일 또는 기간.
- 상품별 품질/세탁/수선 안내, 판매/환불/문의 안내.
- 관련 JOURNAL·ARCHIVE·CARE·CIRCLE 글 링크.
- 외부 링크 미등록 시 구매 CTA 비활성화 및 관리자 오류 표시.
- 과거 회차 판매가와 현재 판매가 혼동 방지.

### 5.2 제품, 선주문 회차와 제작 진행 상태

- 제품 `Product`와 회차 `PreorderRound`는 일대다.
- 회차별 가격·옵션·일정·예상 출고일·외부 URL·상태를 따로 저장.
- 상태 예시: `COMING_SOON`, `OPEN`, `CLOSED`, `IN_PRODUCTION`, `SHIPPING`, `COMPLETED`, `CANCELLED`.
- **판매 접수 상태와 제작 단계 상태는 내부 필드로 구분**하고, UI 문구에서 혼동하지 않는다. 예: 판매 `CLOSED` + 제작 `KNITTING` 가능.
- 일정 기반으로 ‘오픈 예정/마감’ 표시를 보조할 수 있으나, 실제 구매 버튼의 활성 여부는 관리자 승인 상태 + 외부 링크 + 일정 등 조건을 모두 검사한다.
- 상품별 제작 소식은 `ProductionUpdate`로 게시. 단계, 공지일/확인일, 사진, 상세 설명, 지연 안내를 관리한다. 실제 확인 없이 자동 완료 처리하지 않는다.
- 고객 개별 결제/출고/배송 조회는 네이버로 이동하게 한다.
- 종료 상품도 상세 URL 유지. `Piece.###`는 **특별 기획 제품만** 부여하며 모든 상품에 강제하지 않는다.

### 5.3 재주문 희망(로그인 필수)

- 종료되거나 접수 마감된 제품에 관리자 설정으로 `다시 만나고 싶어요` 노출.
- 상품에 실제 등록된 **유효 옵션만** 선택 가능. 비존재 색상·사이즈 노출 금지.
- 로그인 후 원래 제품·옵션 화면으로 복귀.
- 한 회원은 한 제품의 옵션 조합당 최대 1건의 활성 희망 표시. 취소·변경 가능. 서버에서 중복 방지(unique 제약/트랜잭션).
- 버튼 옆에 **“희망 표시는 주문·예약이 아니며 재생산을 보장하지 않습니다.”** 안내.
- 재오픈 알림 수신 동의는 별도 기능(P1)으로, 관심 표시만으로 마케팅 연락을 발송하지 않는다.
- 관리자: 제품/옵션별 고유 인원, 추이, 취소량 집계. 개인정보가 필요 없는 집계에는 가명·익명화.
- 생산 판단은 희망 수와 실제 판매량, 구매 전환율(가설), 원사·공장 MOQ, 원가·마진, 리드타임, 현금흐름을 함께 검토. 희망 클릭 수만으로 자동 생산 결정 불가.

### 5.4 ARCHIVE, JOURNAL, MINDSET

- ARCHIVE: 특별 기획 상품의 Piece. 번호와 디자인 의도·제작 스토리·관련 상품 연결. 번호가 없는 상품도 SHOP에 존치.
- JOURNAL: 리프의 브랜드 철학, 사람과의 이야기, 실제 제작 과정, 의류와 삶에 관한 글. 브랜드 공식 콘텐츠와 고객 게시물 구분.
- MINDSET: `Question`, `Note`, `Small Practice` 형식. 최신/주제별 탐색, 상세 글, 질문 복사 버튼.
- MINDSET **로그인 없이 사용, 사이트 안에 답변 입력폼·자동 저장 없음**, 개인정보 기록 DB 없음.
- CIRCLE 공유는 고객이 새 게시글을 직접 작성하는 별개의 명시적 행동이며 자동 게시/전송하지 않는다.

### 5.5 CIRCLE 커뮤니티

**목표:** Leaf.가 추구하는 삶의 방식에 공감하는 누구나 글을 읽고, 로그인 후 자신의 경험을 나눈다. Leaf. 제품을 구매했는지 검증하지 않는다.

**콘텐츠 유형**

- `MY_WARDROBE` — 오래 간직한 옷, 취향, 스타일링, 이미 가진 옷의 가치.
- `CARE_REPAIR` — 관리·보관·수선·리폼 및 질문.
- `REFLECTION` — 옷과 선택에서 시작해 자신의 일상과 마음에 관한 경험까지 공유.
- `LEAF_ASKS` — Leaf. 관리자가 제안하는 정기 질문; 고객은 댓글 등으로 참여.

**게시글 작성**

- 간편 로그인 필수; 제목, 본문, 카테고리, 사진 최대 3장(선택). 모바일 접근 우선.
- 이미지 형식 JPG/PNG/WebP, 서버에서 MIME/크기/픽셀 검증·안전한 저장·메타데이터 제거·리사이징. 최대 업로드 바이트는 구현·운영 기준으로 설정 (예: 파일당 10MB 상한, 서버 검증).
- 외부 브랜드 옷도 착용·관리·취향 이야기 맥락에서는 허용. 상업 광고, 제휴 홍보 및 중고 직거래 유도는 초기 제한.
- 게시글은 `PENDING` → 관리자 `APPROVED` / `CHANGES_REQUESTED` / `REJECTED`로 상태 처리. 작성자만 비공개 상태 조회.
- 승인 후에만 공개 목록·검색 엔진에 노출. 수정 후 재승인 정책(권장: 본문/이미지 변경 시 재검토), 관리자 액션 로그 보관.
- 로그인 회원 댓글은 기본 즉시 공개, 신고·숨김 기능 적용. 스팸/속도 제한/금칙 행위 대응.
- 회원 본인 글·댓글 수정·삭제, 권한 서버 검증. 신고·삭제·차단 알림은 실현 가능한 채널에 한해.
- 공개 프로필은 닉네임만 기본 표시. 불필요한 개인식별 정보 노출 금지.
- **사진 게시 동의와 외부 마케팅 활용 동의 분리**. 마케팅 활용은 별도 선택 동의 및 출처·철회 정책 필요.

**커뮤니티 안전 원칙**

- 타인의 취향/소비를 비난하거나 특정 가치관 강요 금지.
- 무단 광고·직거래 유도·개인정보 노출·무단 저작물·괴롭힘·차별·허위 관리 정보 제한.
- 자기성찰을 위한 교류이지 전문 의료·심리 상담/치료 아님. 다른 회원에게 진단·치료 지시·위험한 의료 권고 금지.
- 신고 후 검토·숨김·제재, 이의 요청, 반복 위반 차단을 위한 최소 관리 수단.
- 첫 출시 시 커뮤니티 운영 규칙, 개인정보 처리방침, 서비스 이용약관을 실제 운영·법률 요건에 맞게 공개.

### 5.6 EXPERIENCE 프로그램/네이버 예약

- 프로그램 타입: `AROMA_SELF_CARE`, `MINDSET_SESSION`, `CIRCLE_GATHERING`; 모든 프로그램은 온라인/오프라인 구분.
- 프로그램 상세: 소개, 대상, 실제 일정/시간대(KST), 진행 방식, 장소(오프라인) 또는 온라인 참여 방법 안내, 진행자, 정원(확인된 경우), 참가비, 준비물, 신청 마감, 취소·환불 안내, 상태.
- 실제 예약·결제는 외부 네이버 예약 서비스에서 진행하는 것을 **우선 검토**; 사업자·프로그램 유형 개설 가능 여부 확인이 선행 조건.
- Leaf.의 `예약하기`는 관리자에게 등록된 **검증된 외부 URL**로 이동. 새 탭 사용 시 안내와 보안 속성 적용.
- **Leaf. 내부에서 예약·결제 확정을 추정하거나 저장하지 않음**. MY LEAF.에도 실제 예약내역을 보여주지 않음.
- 초기 모집 상태는 `UPCOMING`, `OPEN`, `FULL`, `CLOSED`, `CANCELLED`, `FINISHED` 등 관리자가 수동 표시. 자동 잔여석 데이터처럼 오해를 주지 않는다.
- 종료/마감 상태에서 유효하지 않은 예약 링크 CTA 숨김; 안내 메시지 제공.
- 문의/취소/환불 처리 주체, 최종 예약 확정의 기준은 예약 플랫폼 정책과 일치시킨다.
- 예약 서비스 교체 가능하도록 `bookingProvider`, `externalBookingUrl`과 프로그램 콘텐츠 분리.

### 5.7 MY LEAF. / 계정

- 카카오·네이버 간편 로그인은 **구현 후보**. 제공자별 개발자 등록·사업자 심사·약관·도메인 설정 등 실제 지원 조건 확인 후 적용. 최소 하나 정상 동작을 출시 게이트로 설정.
- 필수: 제3자 제공 고유 ID(내부 member ID로 매핑), 닉네임, 약관 동의 이력. 불필요한 주소·생년월일·전화번호 수집 금지.
- 중복 계정 문제: 동일인 다른 로그인 제공자 계정 자동 병합 금지; 계정 연결은 안전한 소유권 확인이 구현될 때만.
- MY LEAF.: 균형 잡힌 기능/감성 화면 — 재주문 관심 목록, 내 게시글·댓글·승인 상태, 계정 설정/탈퇴.
- 프로그램 예약과 스마트스토어 주문 기록은 **외부 플랫폼에 남음**. Leaf. 마이페이지에서 동일 계정이라는 보장을 하지 않는다.
- 개인정보 삭제/탈퇴 요청, 보유 기간, 동의 철회 처리. 공개 게시글의 계정 탈퇴 시 처리 정책은 출시 전 약관과 일치시킬 것.
- 인증/인가 서버 강제; 관리자 권한은 별도 역할 부여와 접근 통제.

## 8. 기술 방향 (Claude Code 작업 지시)

### 8.1 권장 기본 스택 (잠정)

- **Next.js + TypeScript + App Router** — SEO 및 공개 매거진 콘텐츠/동적 페이지.
- **Tailwind CSS** (또는 동일 수준 토큰 관리) — 반응형 디자인 시스템.
- **PostgreSQL** 기반 데이터베이스 + 인증/파일 스토리지: 운영 가능한 서비스형 플랫폼 1개 선택(예: Supabase). 서비스 선택은 실제 계정·비용·OAuth 지원 확인 후 확정.
- 구조화된 콘텐츠는 DB + 관리자 폼으로 관리. 별도 헤드리스 CMS는 초기 운영 비용/복잡도 대비 필요할 때만 도입.
- 이미지 최적화, CDN/캐시, 배포 환경은 실제 호스팅 환경에 맞춰 선택.
- 네이버 스마트스토어/네이버 예약과 **비공식 스크래핑 또는 자격 증명 공유 방식의 동기화 금지**. P0는 관리자 등록 외부 URL 사용.

### 8.2 보안·개인정보 필수

- 환경변수에 비밀키 보관, 공개 Git 저장소에 커밋 금지.
- HTTPS, 안전한 세션/쿠키, CSRF·XSS·입력 검증·권한 검사, 로그인·댓글·게시물 생성 rate limit.
- 모든 글쓰기/승인/관리 API에서 서버 인증·권한 검증; UI 숨김만으로 보안 처리 금지.
- 이미지 콘텐츠 타입 검증, 업로드 크기·횟수 제한, 비정상 이미지/메타데이터 처리.
- SQL 접근 및 RLS/접근 제어 정책, 최소 권한 운영. 공개 데이터와 비공개 데이터 분리.
- 로그·분석에 개인 성찰 내용/토큰/민감 연락처를 기록하지 않는다.
- 개인정보 처리방침, 이용약관, 커뮤니티 가이드 및 정보 보유기간은 실제 운영자·호스팅·외부 서비스에 맞춰 검토.

### 8.3 접근성·성능·SEO

- 한국어 기본(`lang="ko"`), 영문은 브랜드/섹션명 중심.
- 모바일 우선, 반응형 360px 이상부터 데스크톱까지, 가로 스크롤 오류 방지.
- LCP 이미지 최적화, lazy-loading, 폰트 subset/self-host 가능 여부 검토; 목표 Core Web Vitals 양호 등급.
- 구조적 제목 계층, 이미지 alt, 폼 label, 오류/성공 메시지, 키보드 포커스, 반응형 텍스트.
- 공개 상품/글 메타데이터, OG 이미지, sitemap/robots, canonical, 적절한 구조화 데이터.
- 승인 전 게시물·회원 내부·관리 페이지는 검색 엔진 노출 금지.
- 분석 지표는 가능하면 익명·집계형으로 시작하고 동의/고지 요구사항 검토.

### 8.4 외부 연동 오류 처리

- 외부 링크가 없거나 잘못된 상태에서는 버튼을 숨기고 안내 메시지 제공.
- 링크 클릭 이후 결제·예약 상태는 Leaf.에서 임의 추정 불가.
- 관리자에게 마지막 외부 링크 검토일 표시(가능하면) 및 정기 수동 검수 체크리스트 제공.

## 9. 수용 기준 (Acceptance Criteria)

1. **공개 탐색:** 로그아웃 사용자는 모든 공개 콘텐츠와 CIRCLE 승인 게시글을 열람할 수 있다.
2. **구매 연결:** `OPEN` 회차에서만 유효한 외부 상품 링크 CTA가 노출되고, 종료·미등록 링크에서는 구매 버튼이 보이지 않는다.
3. **상품/회차:** 제품 하나에 2개 이상의 선주문 회차를 만들 수 있고 회차별 가격/일정이 섞이지 않는다.
4. **판매/제작 분리:** 마감된 선주문 제품에 제작 중 공지를 게시할 수 있고, 제작 타임라인이 자동으로 ‘완료’로 바뀌지 않는다.
5. **Piece 번호:** 일반 제품에는 Piece 번호가 없어도 정상 노출되며, 부여된 번호는 중복되지 않는다.
6. **관심 표시:** 로그인 회원이 한 옵션에 희망 표시를 여러 번 눌러도 활성 기록 1건으로 유지된다; 취소가 내 페이지/집계에 반영된다.
7. **로그인 복귀:** 비로그인 사용자가 글쓰기/관심 표시를 누르면 인증 후 원래 맥락으로 복귀한다.
8. **CIRCLE 비공개:** 승인 대기/반려 글과 업로드 이미지는 공개 API/검색·피드에 노출되지 않는다.
9. **CIRCLE 수정/삭제:** 본인만 자신의 게시글·댓글을 수정/삭제할 수 있고 관리자 승인 규칙이 적용된다.
10. **신고:** 공개 게시물·댓글을 신고할 수 있고 관리자 대시보드에서 조치/기록 확인 가능.
11. **MINDSET:** 질문 복사만 가능하며 개인 답변 입력·저장 기능이 없다.
12. **예약:** EXPERIENCE는 검증된 외부 예약 URL로 연결되며 Leaf.에서 결제 성공이나 예약 확정을 표시하지 않는다.
13. **MY LEAF.:** 관심 목록과 내 글·댓글·승인 상태는 본인만 볼 수 있다. 외부 구매·예약 내역을 Leaf. 구매/신청 내역으로 표기하지 않는다.
14. **상태 처리:** 빈 데이터·이미지 없음·삭제 글·404·권한 없음·외부 URL 누락 등에서 이해 가능한 안내를 표시한다.
15. **디자인:** 360px 모바일과 데스크톱에서 핵심 CTA 접근·텍스트 판독·탐색이 가능하다.
16. **관리 운영:** 개발자 도움 없이 제품/회차/제작 업데이트/콘텐츠/프로그램/홈 대표 콘텐츠를 등록·수정할 수 있다.
17. **품질:** 배포 전 접근성 점검, 기본 보안 테스트, 핵심 사용자 흐름 E2E 테스트를 통과한다.

## 10. 측정 지표와 출시 후 검증

### 지표 (초기 기준값 없음, 목표는 런칭 후 설정)

- SHOP: 제품 상세 진입 → 외부 스마트스토어 클릭률, 선주문 콘텐츠 조회, 제품별 제작 공지 조회.
- **주의:** 실제 구매 전환은 외부 주문 정보가 없으므로 클릭률을 판매율로 취급하지 않는다.
- CIRCLE: 승인 게시글 수, 고유 작성자 수, 첫 게시글 작성률, 댓글·신고·승인 처리 시간.
- MINDSET: 질문 페이지 방문, 질문 복사(개인식별 없이 가능할 경우).
- EXPERIENCE: 프로그램 상세 → 외부 네이버 예약 클릭. 실제 예약/참석 실적은 외부 운영 화면에서 별도 확인.
- 재주문: 제품/옵션별 고유 희망 인원, 취소율, 재오픈 기간 실제 선주문 실적(가능할 경우 집계 수준 비교).
- 운영: 주간 관리자 업무 시간, 중복 입력 작업 수, 잘못된 링크/상태 문의 수.

### 검증 계획

- 공개 전 5명 내외의 목표 고객에게 모바일로 ①제품 찾기·구매 링크 클릭 ②CIRCLE 글 읽고 작성 ③프로그램 예약 링크 찾기 테스트.
- 런칭 후 4~8주 동안 실제 사용 데이터를 참고해 메뉴 명칭/콘텐츠 빈도/CTA 위치 조정.
- 초기 기획 가설과 검증 결과를 혼동하지 말 것. 숫자 기반 기준이 확인되지 않았으면 ‘검증 전’으로 남긴다.

## 11. 콘텐츠 운영 가이드 (초기 권장)

- **브랜드 콘텐츠:** 한 달 1~2개 선주문 제품을 중심으로 상품 상세 + Making Updates를 우선 업데이트.
- **JOURNAL:** 제품 또는 브랜드 이야기의 가치가 있을 때 발행, 메인에 자동으로 빈 글 생성하지 않음.
- **CIRCLE:** 브랜드 주도 질문/관리 팁 월 2~4건을 출발점으로 시험; 회원 독립 글은 관리자 승인.
- **MINDSET:** 월 2~4개 질문/짧은 실천(‘TODAY’S QUESTION’이라는 명칭을 쓰더라도 매일 발행 약속 금지).
- **EXPERIENCE:** 온라인/오프라인 모두 등록 가능하지만, 초기 실제 운영 프로그램은 1~2종부터 검증.
- 콘텐츠 운영 빈도는 **권장 실험값**이며 강제 발행 일정이 아님.
- 공개되지 않은 프로그램·상품에 가상 후기나 가짜 진행 상황을 생성하지 않는다.

## 13. Claude Code 구현 순서 및 완료 정의

### 구현 순서

1. **프로젝트 스캐폴딩 및 공식 CI 적용:** `public/brand/` 파일 복사 및 존재 확인, `BrandLogo` 공통 컴포넌트, 헤더/푸터/메타 아이콘, Next.js/TypeScript/스타일 토큰, 라우팅, 배포 환경/시크릿 관리.
2. **공개 콘텐츠 기반:** 상품/회차/ARCHIVE/JOURNAL/MINDSET/EXPERIENCE 데이터와 관리자 CRUD.
3. **홈·SHOP 사용자 화면:** 히어로, 카테고리, 상품 상세, 외부 구매 링크, 제작 진행.
4. **간편 인증 + 권한:** 최소 회원, 로그인 복귀, 계정 설정, 관리자 역할.
5. **CIRCLE:** 게시물/이미지/댓글/승인/신고/내 글·댓글.
6. **재주문 희망 + MY LEAF.:** 중복 방지, 목록, 취소 및 관리자 집계.
7. **운영 안정화:** SEO, 접근성, 외부 URL 안전성, 빈 상태, 개인정보·약관, 테스트, 운영 문서.

### Claude Code에 전달할 구현 규칙

- 이 PRD를 기능의 단일 기준으로 삼되 **`P0`가 아닌 기능을 먼저 구현하지 않는다**.
- 공식 로고는 제공된 `public/brand/leaf-wordmark.png`와 `leaf-symbol.png`를 반드시 사용한다. 원본 두 파일도 보존한다. `Leaf.`를 일반 폰트로 만들어 로고처럼 쓰거나 다른 심볼로 대체하지 않는다.
- 필요한 실제 **상품** 이미지/외부 URL/계정 키가 없으면 디자인용 임시 콘텐츠를 별도 표시하고 프로덕션으로 무단 게시하지 않는다.
- 데이터 스키마/권한/플로우를 먼저 정한 뒤 페이지를 구현한다.
- 공개 상품 페이지와 민감한 회원·관리자 API를 분리하고 테스트한다.
- 처음부터 쇼핑몰 결제/예약 동기화/개인 성찰 기록 시스템을 만드는 식의 범위 확대를 금지한다.
- 각 단계 완료 시: **구현 내역, 테스트 결과, 남은 확인 항목, 실제 동작 URL**을 보고한다.

### 최초 공개의 완료 정의(Definition of Done)

- **첨부 공식 Leaf. 워드마크·심볼이 실제 사이트의 헤더·푸터·파비콘 등에 올바르게 적용되며, 두 원본 이미지가 보존되어 있다.**
- 관리자가 실제 콘텐츠를 등록·수정·발행할 수 있다.
- 방문자는 모바일에서 Leaf. 브랜드·상품·커뮤니티·성찰 질문·프로그램을 쉽게 탐색한다.
- 유효한 외부 구매/예약 페이지로 이동하며 내부 사이트에서 결제/예약 성공을 허위 표시하지 않는다.
- 로그인 이용자는 CIRCLE 참여 및 재주문 희망을 관리할 수 있다.
- 게시글 승인/신고, 권한·보안·기본 정책 안내가 작동한다.
- 핵심 사용자 흐름 테스트와 실제 기기 확인 후 배포한다.

## 14. 최종 요약

**Leaf.는 매거진형 쇼핑몰, 옷을 오래 사용하는 이야기, 자기성찰 콘텐츠, 작고 진정성 있는 관계를 연결하는 플랫폼이다.** 초기에는 외부 커머스·예약 시스템을 활용해 거래 운영의 부담을 줄이고, Leaf. 자체 사이트는 콘텐츠와 커뮤니티의 경험을 깊게 만드는 데 집중한다. 사업과 고객 참여 데이터가 축적된 후 자체 결제, 순환 마켓, 오프라인 모임 등으로 확장한다.
